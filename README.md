# Campus Incident Reporting App

A Flutter mobile app that lets students report campus problems (water and electricity outages, broken facilities, damaged furniture, sanitation and safety issues) and lets authorised campus staff review them and update their status until they are resolved.

Built for Individual Assignment 2 (Formative) by **Oladeji Toluwani Jephthae**.

- **Repository:** https://github.com/ToluwaniOladeji/OladejiToluwani_Assignment2.git
- **Demo video:** Campus_incident_app Demo Video
- **Technical report:** submitted separately as a PDF through Canvas

## Features

**Students**
- Register with an ALU email and verify it before using the app
- Submit a report with a category, title, location, description and an optional photo (camera or gallery)
- Browse all campus reports in a live list; search by text and filter by status and category
- Open a report to see its photo, details, a four-stage progress bar and a timeline of every status change with staff notes
- Follow their own reports in the **Mine** tab; withdraw a report while it is still *Submitted*

**Staff**
- Dashboard with a count of reports per status, a resolution rate and a queue of reports awaiting review
- Change a report's status (Submitted, In review, In progress, Resolved) and add a note for the reporter
- See the reporter's email and delete reports

**Security**
- ALU-only access: the registration form checks the email domain, and every account must verify its email
- Role-based access control enforced in Firestore security rules (not only in the UI)
- Staff accounts cannot be created from inside the app

## Tech stack

| Area | Choice |
|---|---|
| Framework | Flutter (Dart), Material 3 |
| Authentication | Firebase Authentication (email and password, email verification) |
| Database | Cloud Firestore |
| Image storage | Cloudinary (unsigned upload preset); see the note below |
| State management | Riverpod (`flutter_riverpod` 2.x) |
| Other packages | `image_picker`, `intl`, `http` |

**Why Cloudinary instead of Firebase Storage?** Firebase Storage required the paid Blaze plan on my Firebase project. All image handling lives in one class (`lib/repositories/storage_repository.dart`), so switching back to Firebase Storage only means changing that file.

## Architecture

The app has four layers. Each layer only talks to the one below it, and screens never call Firebase directly.

```
Screens and widgets  ->  Riverpod providers  ->  Repositories  ->  Firebase / Cloudinary
```

```
lib/
  main.dart
  firebase_options.dart      generated by `flutterfire configure`
  models/                    Incident, HistoryEntry, enums (category, status)
  repositories/              auth_repository, incident_repository, storage_repository
  providers/                 auth_provider, incident_provider
  screens/
    auth/                    login, register, verify email, auth gate
    student/                 home, submit report
    staff/                   dashboard
    shared/                  report list, report detail, profile
  widgets/                   incident card, status chip, filter pill, summary tile, ...
  theme/                     colours and theme
  utils/                     validators, error messages, time formatting
test/
  validators_test.dart
firestore.rules
storage.rules
```

### Firestore data model

- `users/{uid}`: `email`, `displayName`, `role` (`student` or `staff`), `createdAt`
- `incidents/{incidentId}`: `title`, `description`, `category`, `status`, `location`, `imageUrl`, `reporterId`, `reporterEmail`, `createdAt`, `updatedAt`, `updatedBy`
- `incidents/{incidentId}/history/{entryId}`: `status`, `changedBy`, `note`, `changedAt`

Categories: `water`, `electricity`, `facilities`, `furniture`, `sanitation`, `safety`.
Statuses: `submitted`, `in_review`, `in_progress`, `resolved`.

## Getting started

### Prerequisites

- [Flutter SDK](https://docs.flutter.dev/get-started/install) and Android Studio with an Android emulator (or a physical Android device)
- A Firebase project
- A free [Cloudinary](https://cloudinary.com) account
- Node.js (for the Firebase CLI)

### 1. Clone and install

```bash
git clone https://github.com/ToluwaniOladeji/OladejiToluwani_Assignment2.git
cd OladejiToluwani_Assignment2
flutter pub get
```

### 2. Connect Firebase

```bash
npm install -g firebase-tools
firebase login
dart pub global activate flutterfire_cli
flutterfire configure
```

Choose your Firebase project and the Android platform. This generates `lib/firebase_options.dart`.

In the Firebase console:

1. **Authentication, Sign-in method:** enable **Email/Password**.
2. **Firestore Database:** create a database, open the **Rules** tab, paste the contents of `firestore.rules` and click **Publish**.

> If the app shows "You do not have permission to do that" right after login, the Firestore rules have not been published to the project yet.

### 3. Configure Cloudinary

1. In Cloudinary, go to **Settings, Upload, Upload presets** and create a preset with **Signing mode: Unsigned**. Restrict it to image formats and a maximum file size.
2. Open `lib/repositories/storage_repository.dart` and set your values:

```dart
static const _cloudName = 'your-cloud-name';
static const _preset = 'your-unsigned-preset';
```

### 4. Run

```bash
flutter run
```

Android needs `minSdk` 23 or higher (set in `android/app/build.gradle.kts`).

## Creating a staff account

Every new account starts as a student. To make a staff account:

1. Register a second account in the app with another ALU email and verify it.
2. In the Firebase console, open **Authentication, Users** and copy that account's **User UID**.
3. Open **Firestore Database, Data, `users`**, open the document with that UID and change `role` from `student` to `staff`.
4. Log out and log back in with that account.

## Troubleshooting

| Problem | Fix |
|---|---|
| Blank screen on the emulator | Run `flutter run --no-enable-impeller`, switch the emulator graphics to **Software**, or use a different emulator image (API 34 or 35) |
| Compile errors about `StateProvider` or `AutoDisposeAsyncNotifier` | This project uses Riverpod 2.x. Run `flutter pub add flutter_riverpod:^2.6.1` |
| `permission-denied` after login | Publish `firestore.rules` in the Firebase console and confirm the app is connected to the same project |
| Photo upload fails | Check the Cloudinary cloud name, and that the preset exists and is **Unsigned** |
| Gallery shows no images on the emulator | Drag a photo onto the emulator, then open the Files or Photos app once so Android indexes it |
| `Cannot find firebase_options.dart` | Run `flutterfire configure` from the project root |

## Known limitations

- Staff accounts are promoted manually in the Firebase console; a production system would use an admin tool or custom claims set by a trusted backend.
- Unsigned Cloudinary uploads are not suitable for production; use signed uploads or Firebase Storage.
- Deleted reports do not remove their images from Cloudinary.
- Location is free text, and there are no push notifications.
- Search runs on the device over all loaded reports, which suits a campus-sized dataset.
